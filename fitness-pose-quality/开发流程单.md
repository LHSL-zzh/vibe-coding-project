# 健身动作质量评估 (fitness-pose-quality) — 开发流程单

> 构思：使用人体关键点检测（pose estimation）识别健身动作的质量，
> 给出动作是否标准、错误部位、质量评分与次数统计。

## 1. 项目目标

摄像头/视频输入 → 人体关键点检测 → 动作质量评估（角度/对齐/幅度）
→ 实时反馈（画面叠加提示 + 质量分 + 次数/组数统计）

首个版本支持 3 个动作：深蹲、俯卧撑、哑铃弯举（可扩展）。

## 3. 技术选型

| 模块 | 方案 | 备注 |
|---|---|---|
| 关键点检测 | **MediaPipe BlazePose**（33 点，CPU 实时）为主，YOLO-pose 为备选 | BlazePose 原型快、单人多动作友好；YOLO-pose 多人在线更强、生态熟悉 |
| 动作识别 | 关键点几何特征 + 轻量分类（规则优先，LSTM 后期可选） | 先 3 个动作，规则可解释 |
| 质量评估 | **规则几何引擎**：关节角度/身体对齐/动作幅度 vs 阈值 | 可解释、无需标注数据；后续可叠加序列模型打分 |
| 界面 | OpenCV 实时叠加（首版），可选 Gradio/Web 展示 | 最快出 demo |
| 语言 | Python 3.11+ | 复用 ~/.venvs/vp 环境模式 |

## 4. 系统架构

```
摄像头/视频文件
    │
    ▼
关键点检测 (MediaPipe BlazePose / YOLO-pose)
    │  33 关键点 (x, y, visibility)
    ▼
骨架可视化 (OpenCV 画关节点+连线)
    │
    ▼
动作识别 (几何特征 → 当前动作: 深蹲/俯卧撑/弯举)
    │
    ▼
质量评估引擎 (规则: 角度/对齐/幅度 → 错误类型 + 质量分 0-100)
    │
    ▼
实时反馈 (画面叠加: 骨架+提示文字+质量分+次数) → 统计输出
```

## 5. 里程碑

### M0 环境与数据（0.5 天）
- [ ] 建项目骨架（目录、venv、依赖：mediapipe/opencv/numpy）
- [ ] 确认视频源：本机摄像头 / 测试视频
- [ ] 评估公开数据集（AQA-7 / Fitness-AQA）作为后期训练数据

### M1 关键点检测接入（1 天）
- [ ] 单帧图片 → 33 关键点输出（MediaPipe）
- [ ] 骨架绘制（关节点 + 连线）可视化
- [ ] 视频流逐帧处理，FPS 显示

### M2 几何规则引擎（1-2 天）
- [ ] 关节角度计算工具（肘/膝/髋/躯干倾角，向量夹角）
- [ ] 深蹲规则：膝屈曲角度、髋折叠、膝盖过脚尖、深度（大腿平行）
- [ ] 俯卧撑规则：肘角变化范围、躯干直线度（髋下沉/塌腰）
- [ ] 弯举规则：肘固定、前臂幅度、躯干晃动
- [ ] 规则配置化（yaml：动作→角度阈值→错误提示文案）

### M3 动作识别与质量分（1-2 天）
- [ ] 关键点序列 → 动作类型识别（先规则+简单分类）
- [ ] 质量分模型：错误项扣分 → 0-100 分（每帧/每次动作）
- [ ] 次数/组数统计（动作完成周期检测：关键角度过阈值翻转）

### M4 实时评估整合（1 天）
- [ ] 摄像头实时管线：检测→识别→评估→叠加反馈
- [ ] 错误提示实时显示（如"膝盖内扣""塌腰"）
- [ ] 质量分曲线 + 动作统计落盘

### M5 打磨与部署（1 天）
- [ ] 多动作切换、阈值可调（用户体型差异）
- [ ] 误报优化、FPS 优化
- [ ] README + 使用文档 + 演示视频

## 6. 验证标准

| 指标 | 目标 |
|---|---|
| 关键点检测帧率 | CPU ≥ 25 FPS（MediaPipe） |
| 关节角度精度 | 与人工标注误差 ≤ 5° |
| 动作识别准确率 | 3 动作 ≥ 90% |
| 质量评估一致率 | 与人工评分一致 ≥ 85%（初版） |
| 反馈延迟 | 画面叠加 ≤ 100ms |

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 单摄像头视角受限（侧/正面遮挡） | 建议侧向 45° 拍摄；文档说明最佳视角 |
| 规则阈值不通用（体型/柔韧性差异） | 阈值 yaml 可调 + 用户校准模式 |
| 质量评估主观性强 | 以"可量化的错误"（角度/幅度）为硬指标，主观分后期用模型 |
| 需要标注数据训练 | 规则引擎不依赖标注；分类模型优先用公开数据集 |
