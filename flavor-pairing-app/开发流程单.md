# 风味搭配指南 (flavor-pairing-app) — 开发流程单

> 构思：依据「风味搭配理论」做一个指导食物/饮品制作的 APP——
> 每种食材的主要风味可量化成风味坐标（一条"风味光谱"），
> 光谱上位置相近的食材天然适合搭配。
> 用户输入手头食材 → APP 给出能搭的食材/风味方向 → 指导怎么做（调味、处理、菜式方向）。

## 1. 项目目标

用户选择 1~N 种手头食材 → APP 计算每种食材在"风味光谱"上的位置 →
找出与它们风味相近（光谱距离近）的可搭食材与风味方向 → 输出做法指导：

- 食材风味画像（在光谱上的位置、主要风味维度雷达）
- 推荐搭配（可搭食材 top-k + 搭配理由）
- 做法指导（风味方向 → 怎么调味、怎么处理、适合什么菜式）
- （进阶）根据"现有食材 + 推荐搭配"生成一道具体菜品建议

形态：**移动端优先的网页应用**（PWA，可"添加到主屏幕"当 APP 用），无后端，部署 GitHub Pages。

## 2. 理论与开源项目调研结论

### 2.1 「风味光谱」理论溯源（先澄清概念）

**不存在现成的权威"一维风味光谱"标准**，但有一整套可工程化的风味搭配理论与数据：

| 来源 | 内容 | 与"光谱"的关系 |
|---|---|---|
| **Ahn et al. 2011**《Flavor network and the principles of food pairing》(Scientific Reports) | 用挥发性风味化合物网络分析 56,498 份菜谱：**北美/西欧菜**显著遵循"共享风味化合物 → 搭配"，**东亚菜（中/日/韩）反而回避共享化合物** | 学术奠基；"相近即搭"只在西式菜系成立——**必须做成设计风险/可选模式** |
| **《The Flavor Matrix》** (James Briscione, 前 IBM Chef Watson 主厨) | 把食材按共享风味分子排布成二维"风味图谱"，每格标注经典搭配 | 最接近用户设想的"光谱可视化"成品形态 |
| **《The Flavor Bible》**(Karen Page) | 大厨经验数据：每种食材的搭配表 | 权威经验数据，多家开源项目的数据源 |
| **foodpairing.com / Inspire KG** | Bernard Lahousse 商业公司；公开 RDF 知识图谱（CC BY 4.0）：食材香气/味道/口感/搭配 | 可下载的现成搭配知识图谱 |
| **FlavorDB** (IIT Delhi, cosylab.iiitd.edu.in) | 免费数据库/API：936 食材 × 22,546 风味分子 + 描述词 | 分子级数据源，可算"食材→风味向量" |
| **VCF**（Wageningen 大学） | 食物挥发性化合物数据库 | Ahn 2011 原始数据出处 |
| 风味轮（SCAA/WCR 咖啡等） | 品类专用风味分类 | 术语/分族灵感（果香/花香/坚果/焦糖…） |

**工程化结论**：把"光谱"实现为「食材 → 多维风味向量 → 可视化一维轴/降维投影 + 距离计算」。
MVP 用可解释的**专家风味维度表**（甜/咸/酸/苦/鲜/辣/油脂 + 香气族），进阶可接入 FlavorDB 分子向量降维（PCA/t-SNE）。

### 2.2 GitHub 现有开源项目

| 项目 | Star | 技术栈 | 说明 |
|---|---|---|---|
| dmis-lab/KitcheNette | ★85 | Python/PyTorch | Siamese 网络预测食材搭配（IJCAI-2019），300K 配对评分标注。**搭配引擎学术参考** |
| lingcheng99/Flavor-Network | ★104 | Python/networkx | 复现 Ahn 2011：1530 食材风味化合物网络（36,781 边），食谱投影风味空间做推荐。**数据与方法最贴近本理论** |
| Pepton21/flavor-network | ★7 | Java | Ahn 论文结果复现 |
| foodpairing/inspire_kg | ★5 | RDF/JS | Foodpairing 官方开源知识图谱（CC BY 4.0）：类目树、102 食材、风味感官、官方搭配。**可直接下载的数据源** |
| max-mapper/flavors | ★27 | JS 移动网页 | 查食材风味搭配（数据源自《Culinary Artistry》书）——**形态最接近本项目 MVP** |
| levi006/FlavorNet | ★18 | JS | 基于风味化合物分析的交互式搭配参考，可按菜系过滤 |
| food-tools/flavor-map | ★14 | React+D3 | 《The Flavor Bible》食材搭配图谱可视化 |
| jamesccupps/FlavorForge | ★4 | Python | 分子风味引擎程序化生成菜谱（gastronaut 风格） |
| RoaldSchuring/wine_food_pairing / frenetic-be/MLFoodPairing | ★25/25 | Jupyter | 酒食搭配 / ML 搭配实验 |
| burhanahmed1/FlavorMatch | ★3 | Python | 食材为中心、余弦相似度推荐引擎 |

**结论**：
- 领域有**学术+商业双层成熟度**：理论（Ahn 2011）、分子数据（FlavorDB/VCF）、商用 KG（Inspire KG）都开放可用
- 但**面向普通用户"输入食材→指导做法"的成品 APP 仍稀缺**（现有多为研究者工具/可视化 demo），空白清晰
- 形态参照 max-mapper/flavors（移动网页）+ 算法参照 KitcheNette/余弦相似度；MVP 数据先用手工风味维度表，避免一上来就啃分子数据库

## 3. 技术选型

| 模块 | 方案 | 备注 |
|---|---|---|
| 应用形态 | 移动端优先网页 + PWA（无构建/轻构建），GitHub Pages 部署 | vibe coding 仓库惯例；"APP"通过 PWA 添加到主屏幕实现 |
| 前端 | 原生 HTML/CSS/JS（零依赖，延续 zhouyi-app 惯例）；光谱可视化用 SVG/Canvas | 交互变复杂时可局部引入轻量库 |
| 数据 | `flavor_data.json`：食材 ×（id、中英文名、类别、8~10 维风味分数 0-5、经典搭配、做法标签） | MVP 先 60~100 种高频食材；来源标注（Flavor Bible 风格经验值 + FlavorDB 校正） |
| 光谱/向量 | 专家风味维度表为**主坐标**（可解释）；按需叠加 PCA 投影做"一维光谱轴"展示 | 维度：甜/咸/酸/苦/鲜/辣/油脂/酒精 + 香气族（果香/花香/草本/坚果/焦糖/烘烤） |
| 推荐算法 | 加权欧氏/余弦距离 top-k + 规则过滤（排除冲突类目、同类去重） | 复杂度低、可解释：推荐理由 = "与 XX 共享 YY 风味维度" |
| 做法指导 | 规则模板：风味方向 → 调味建议/处理方式/菜式方向（如"甜+酸→可做糖醋/酸甜口，先腌后烹"） | MVP 模板化输出；进阶接 LLM 生成完整菜谱 |
| 双语 | 中文为主（界面+食材名），英文食材名留字段 | 数据来源多为英文，便于对照 |

## 4. 系统架构

```
用户选食材（搜索/点选，1~N 种）
    │
    ▼
风味查询：食材 → flavor_data.json 风味向量（多维分数 + 香气族标签）
    │
    ▼
光谱定位：多维向量 → 一维/低维投影展示（食材在光谱轴上的位置 + 雷达画像）
    │
    ▼
搭配引擎：与全库食材算距离 top-k
    │  规则过滤（类别冲突/重复）
    ▼
推荐结果：可搭食材 + 搭配理由（共享哪些风味维度）+ 风味方向总结
    │
    ▼
做法指导：风味方向 → 模板生成（调味/处理/菜式/饮品建议）
    │
    ▼
（进阶）LLM：现有食材+推荐 → 生成一道完整菜品做法
```

## 5. 里程碑

### M0 风味数据准备（1 天）
- [ ] 确定风味维度体系（基础味 6 + 香气族 8，共 14 维打分 0-5，附"维度→中文描述"）
- [ ] 整理 60~100 种高频食材（肉/菜/果/香料/饮品原料），每种：中英文名、类别、维度分、经典搭配 3-5 个
- [ ] 校验脚本：维度分完整性、重复食材、经典搭配双向一致性抽查
- [ ] 出处记录：人工打分参考《Flavor Bible》经验值，抽查对照 FlavorDB 描述词（flavordb.info）

### M1 光谱与搭配引擎（0.5-1 天）
- [ ] 食材→向量加载模块；加权距离/余弦相似度函数
- [ ] 一维光谱投影：主成分(PCA)或手工主轴（如"清淡爽口←→浓郁厚重"）排序展示
- [ ] 推荐 top-k + 过滤规则（排除冲突、控制类别多样性）
- [ ] 推荐理由生成（"草莓 与 巧克力 共享 甜/果香/可可"）
- [ ] 单元测试：已知搭配命中（草莓→巧克力/香草、番茄→罗勒/马苏里拉…）、冲突剔除（豆浆+醋类）

### M2 界面（1-1.5 天）
- [ ] 首页：食材搜索/点选（按类别分组：蔬菜/水果/肉禽/水产/香料/乳品…）
- [ ] 光谱可视化：已选食材在光谱轴上的位置 + 每食材风味雷达图（SVG）
- [ ] 推荐面板：可搭食材卡片（距离/理由/风味方向）
- [ ] 做法指导页：模板输出（调味建议/处理方式/菜式方向），可换随机变体
- [ ] 移动端优先响应式 + PWA manifest（可添加到主屏幕）

### M3 数据与内容扩充（1 天）
- [ ] 食材扩到 150+；做法模板扩到按类别覆盖（热菜/凉拌/甜品/饮品/烘焙）
- [ ] 常见"冲突搭配"黑名单规则（经验规则库）
- [ ] 中文风味描述词表完善（让理由读起来自然）

### M4 打磨与部署（0.5-1 天）
- [ ] 空结果兜底（给的食材太少/太偏时引导换料）
- [ ] 可选 LLM 模式（有 API key 时生成完整菜谱；无 key 用模板）
- [ ] GitHub Pages 部署 + README（理论说明、数据来源、免责声明：风味建议非营养学建议）

## 6. 验证标准

| 指标 | 目标 |
|---|---|
| 经典搭配命中率 | 手工测试集 30 组经典搭配（草莓×巧克力、番茄×罗勒、猪肉×大蒜…）top-5 命中 ≥ 80% |
| 冲突剔除率 | 已知冲突组合（如豆浆×醋类凝乳场景）不出现在 top-10 ≥ 90% |
| 光谱一致性 | 同类食材（柠檬/青柠/橙；迷迭香/百里香/牛至）投影位置相邻 |
| 推荐可解释性 | 每条推荐都带共享风味理由，抽查 20 条理由与直觉一致 ≥ 85% |
| 数据覆盖 | MVP 60+ 食材全维度分完整；扩充版 150+ |
| 页面可用性 | 移动端（375px）与桌面均正常；无 console 报错 |

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| "风味光谱"无权威一维标准，概念易被质疑 | 明确定义：多维风味向量 + 可解释降维轴；文档/README 说明这是工程近似而非物理定律 |
| **Ahn 2011：东亚菜系反例**（中餐回避共享化合物） | 推荐逻辑以"风味共鸣"为主旨；界面注明理论适用范围，后续可加"互补/对比"模式（中式思路：如酸辣、苦瓜×咸蛋这类对比搭配） |
| 风味打分主观 | 打分表多人/多次校验 + 对照《Flavor Bible》经验值 + FlavorDB 描述词抽查；所有来源写入数据注释 |
| 做法指导只是模板非菜谱 | MVP 定位"风味方向指导"不冒充完整菜谱；LLM 模式可生成可执行菜谱（标注 AI 生成） |
| 数据源英文、中文术语不统一 | 双字段存储（中文名+英文名+别名），维度词表统一 |
| FlavorDB/Inspire KG 需联网 | MVP 不依赖外部 API，全部数据本地打包；联网仅用于扩充数据阶段 |
| 免责与边界 | 只讲风味搭配，不做营养/健康/过敏建议（README 声明） |
